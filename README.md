## Technical stack

| Layer | Choice | Green IT justification |
|-------|--------|------------------------|
| Front-end | HTML5 + CSS3 + 0 JS framework | No bundle, no hydration, no tree shaking needed because no heavy JS. |
| Templating | Native template literals | Zero dependency, server-side generation, no client runtime. |
| Back-end | Node.js (Express) | Well-known ecosystem, reasonable memory footprint. |
| Database | SQLite via `node:sqlite` (Node >= 22.5) | Zero native dependency, no separate DB server, no extra network connection. |
| Auth | bcryptjs + express-session | bcryptjs is pure JS (no native build). Cookie HttpOnly + SameSite Lax. |
| Hosting target | Render / Fly.io / Railway | Free tier, automatic gzip/brotli, Git-based deployment. |

No heavy framework (no React, no Tailwind, no jQuery). System fonts only. No images (favicon is an inline SVG data URI).

## Features

- Home page presenting the project and the eco approach.
- **Coffees** page: paginated list (10 per page), filters by variety and origin.
- **Coffee (detail)** page: full sheet of a coffee.
- **Sign up / Log in** with sessions, bcrypt password hashing, server-side validation.
- **Users CRUD** (admin only, paginated 20 per page).
- **Coffees CRUD** (logged-in users; edit/delete restricted to owner or admin).
- Explicit confirmation before deletion (`confirm()` dialog, no ajax).
- **Approach** page detailing the Green IT choices.
- Automatic dark mode via `prefers-color-scheme`.
- Security headers (CSP, X-Frame-Options, nosniff, Referrer-Policy).

## Local setup

Requirements: **Node.js >= 22.5** (for `node:sqlite`). Recommended: Node 24 LTS (sqlite stable, no experimental warning).

```bash
# 1. Clone
git clone https://github.com/<user>/green-coffee.git
cd green-coffee

# 2. Install (74 packages, no native build)
npm install

# 3. Environment variables
cp .env.example .env
# Edit .env and change SESSION_SECRET

# 4. Initialise the DB (schema + admin users + 10 seed coffees)
npm run init-db

# 5. Run
npm start
# or in dev with file watching
npm run dev
```

The site is then available on http://localhost:3000

## Deployment

Recommendation: **Fly.io** or **Render** (free tier, automatic gzip/brotli, automatic redeploy on push to main).

### Render (example)

1. Connect the GitHub repo to Render.
2. New Web Service > Build command: `npm install`
3. Start command: `npm run init-db && npm start`
4. Env vars: `NODE_ENV=production`, `SESSION_SECRET=<long random>`
5. The service is exposed at `<name>.onrender.com`.

The `.env` file must never be committed. Secrets go through the platform's environment variables.
